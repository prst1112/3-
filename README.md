# Гарант Бот

Telegram-бот для безопасных сделок между продавцом и покупателем. Бета-версия:
все платежи подтверждаются администраторами вручную, реальных переводов бот не проводит.

## Стек

- Python 3.11+, aiogram 3
- SQLite (aiosqlite) — без веб-бэкенда, обычный бот на reply/inline-кнопках
- FSM (aiogram) — сценарии создания сделки и добавления реквизитов

## Как это работает

1. **Продавец**: «Создать сделку» → выбирает валюту (Карта / Gram (TON) / Звёзды) →
   вводит сумму → вводит описание товара → бот выдаёт номер сделки и ссылку вида
   `t.me/<bot>?start=<номер>`.
2. Продавец отправляет ссылку покупателю.
3. **Покупатель** переходит по ссылке → видит карточку сделки и мини-профиль продавца →
   жмёт «Оплата через поддержку» (саппорт вручную объясняет, куда и как платить) →
   после оплаты жмёт «Я оплатил» и прикладывает скриншот.
4. Скриншот и вся информация о сделке уходят **обоим админам** личным сообщением с
   кнопками «Подтвердить» / «Отклонить».
   - Подтвердил → сделка закрыта, продавцу и покупателю приходят уведомления,
     баланс продавца в профиле увеличивается на сумму сделки.
   - Отклонил → продавцу и покупателю приходит уведомление об отказе, покупатель
     может попробовать оплатить повторно.
5. Запрос на удаление сделки может отправить **любой** участник в любой момент —
   уходит админам, которые удаляют сделку или отклоняют запрос.

Баланс в профиле считается автоматически (сумма завершённых сделок как продавец),
реальных выводов средств нет — кнопка «Вывод» показывает заглушку «в разработке».

**Оплата картой привязана к реквизитам.** Чтобы создать сделку с оплатой картой,
у продавца должна быть заранее привязана хотя бы одна карта (Реквизиты → Добавить
карту). При создании сделки вместо общей кнопки «Карта» показываются конкретные
привязанные карты продавца (флаг страны + номер) — выбранная карта сохраняется
вместе со сделкой и видна и покупателю, и админу при подтверждении. Если карт нет,
кнопка карты не появляется, бот подсказывает сначала привязать её. Gram (TON) и
Звёзды по-прежнему доступны без привязки.

## Если админам не приходят сделки на проверку

Telegram запрещает боту первым писать пользователю, который никогда не открывал
с ним диалог. **Оба админа должны хотя бы раз нажать /start в самом боте** —
иначе уведомления о новых сделках/запросах на удаление не долетят, и это не будет
видно нигде, кроме логов.

Чтобы проверить причину, смотри логи Railway (Deployments → View Logs):
- При старте бот пишет `Загружены ADMIN_IDS: [...]` — сверь, что там правильные
  числовые ID.
- Если отправка админу не удалась, теперь в логах будет полная трассировка
  ошибки с указанием, какому админу и по какой сделке не отправилось.

## Установка

```bash
git clone <ваш-репозиторий>
cd guarant_bot
python3 -m venv venv
source venv/bin/activate       # Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
```

Заполните `.env`:

```
BOT_TOKEN=токен_от_BotFather
ADMIN_IDS=айди_админа_1,айди_админа_2
SUPPORT_USERNAME=helpes_deal
DB_PATH=guarant_bot.db
```

ID администратора можно узнать, например, через @userinfobot. Первый админ по ТЗ — `@grozahvh`, узнайте его числовой user_id и впишите в `ADMIN_IDS`.

Запуск:

```bash
python bot.py
```

## Деплой на Railway

1. Запушьте репозиторий на GitHub (не забудьте `webapp`/статика тут не нужна — это
   обычный бот без Mini App, всё содержимое уже в `.py`-файлах).
2. Создайте новый проект на Railway из репозитория.
3. Задайте переменные окружения `BOT_TOKEN`, `ADMIN_IDS`, `SUPPORT_USERNAME` в
   настройках сервиса.
4. **Важно**: это background-воркер, а не веб-сервер — он не слушает `$PORT`.
   В `Procfile` уже указано `worker: python bot.py`. Убедитесь, что Railway
   запускает процесс именно как worker, а не пытается ждать HTTP-ответа на порту —
   иначе может посчитать деплой нездоровым. Если Railway ругается на отсутствие
   веб-порта, в настройках сервиса отключите health-check по HTTP (Settings →
   Healthcheck) — для воркера он не нужен.
5. Если нужна персистентность БД между деплоями — подключите Railway Volume и
   укажите `DB_PATH=/data/guarant_bot.db` (аналогично вашему крипто-боту).

## Структура проекта

```
guarant_bot/
├── bot.py                 # точка входа
├── config.py               # переменные окружения
├── database.py              # вся работа с SQLite
├── locales/                 # тексты ru/ua/en
├── keyboards/                # reply- и inline-клавиатуры
├── states/                    # FSM-состояния
├── handlers/
│   ├── start.py               # /start + диплинки на сделки
│   ├── deal_create.py          # сценарий создания сделки (продавец)
│   ├── deal_view.py             # карточка сделки, "Я оплатил", запрос удаления (покупатель)
│   ├── admin.py                  # подтверждение/отклонение сделок и удалений
│   ├── profile.py, requisites.py, language.py, support.py, misc.py
└── utils/helpers.py           # генерация номера сделки, форматирование сумм
```
